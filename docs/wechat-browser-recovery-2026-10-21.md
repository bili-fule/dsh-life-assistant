# 微信助手浏览器连接故障（2026-10-21）

## 症状与原因

微信消息能入库，发送故障通知也成功，但原文 #228–#236 处理失败：
`mcp-client(playwright-mcp): initial connection or tool synchronization failed`。
夜间整理亦被相同错误阻断。

浏览器代理的 `TasksMax=24` 同时限制 Node 与 Docker CLI 的全部线程。
已有浏览器连接占用线程后，新 Docker CLI 无法正常启动，新的 MCP 连接提前关闭。
服务显示 active 并不能证明新会话能握手。

## 修复

将浏览器代理服务的 `TasksMax` 提高至 128，覆盖最多四个浏览器连接的
Docker CLI 线程与清理命令。浏览器容器自身的进程、内存和权限限制保持原配置。
生产 service 文件与当前生效值均已更新，无需重启主助手。

## 已验证

同一 `dsh-life` 用户经 Unix socket 发起 MCP initialize：调整前连接直接关闭，
先将上限临时调整至 64 后立即获得正常协议回应，再持久设置为 128。
原文 #228 通过现有管理接口重试后已完成，回复 #204 的微信发送回执为 `sent`。
其余失败批次 #229、#230、#231–#233、#234–#236 已通过管理接口重新排队，
按原批次顺序恢复处理，不修改原始消息或历史会话。
