# 动机、持续意图与选择性学习

状态：0.8.0 已部署并通过自动化测试；上线与真实行为验收见 [运行状态](../deploy/STATUS.md)。

0.12.0 起另有可选的动机层：`self_options / self_choose / self_appraise / self_preferences` 分开保存期待、实际体验和有界偏好，与本文件的关切、下一步和学习意图并存。字段、规则与验证见 [以开心为方向的自主选择](humanlike-motivation.md)。本文件的五类满足记录（`yoyo_self`）仍是主体自己的粗描述，不等于新动机系统。

## 运行方式

QQ 群、私聊共用一个 DSH 原生 Agent；微信使用独立 Agent、Session、工作区和数据库。插件提供工具、持久状态和事实事件，不另写模型循环。模型选择关切、行动与是否发言，宿主负责权限、预算、定时和回执。

持续流程：经历 → 具体关切 → 下一步意图 → 有限行动 → 实际反馈 → 继续、调整、等待或放弃。表达、好奇等类别仅供理解，不设置必须填满的需求槽，不靠机械制造“孤独”强迫社交。

## 三个工具

### yoyo_concern

无参数列出当前可见关切。创建需提供 `title / why / origin / next / doneWhen / stopWhen`；`id` 更新。状态为 `active / waiting / done / abandoned`，可设置未来三十天内的 `reviewAt` 毫秒时间，null 表示没有定时复查。

`origin` 是主体对起因的描述，不能当作已核实的事实证据。每条关切继承调用视图的全部来源范围；从更宽视图修改后也继承更宽来源，不能把私聊输入洗成公开资料。更新前重新验证视图授权。

复查回到创建/更新时的有效原生资料视图。到期机会交给一条持久活动请求后即消费；失败保留失败轨迹，不快速自动重试。比较原到期值后清空，避免覆盖运行中设置的新时间。撤权记录不唤醒其他窗口。

### yoyo_feedback

参数为关切 `id`、`outcome`、`decision`（continue/revise/wait/done/abandon），可附实际工具 `receipt`。未引用回执时明确标为 `self_report`；引用可见回执时标为 `tool_receipt`。这只证明引用了结果，不能证明模型对结果的解读正确。

反馈独立保留，不自动宣称关切成功。需要改变下一步、完成标准或状态时再次调用关切工具。模型不可用自己的记忆保存、反馈或满足度工具回执为自己制造执行证明。

### yoyo_learning

理解别人的表达不等于采纳为自身风格。无参数查看学习意图；创建需要：

- `trait`：欣赏的具体特质。
- `admiration`：为什么欣赏，不能只写“这个人出现得多”。
- `trial`：怎样有限尝试。
- `sources`：同一真实发言者至少两条独立直接消息及逐字引用。

稳定身份是平台、接入账号、真实发送者 ID 的组合。昵称、转发、引文中的姓名都不能代替身份。不同人的证据不能拼接；转发消息不作为本人习惯证据。

状态为 `proposed → trial → adopted`，可 `retired` 停止沿用。保留前必须已有 trial，并提供复查 `review` 及实际尝试 `trialReceipt`：已确认送达的 yoyo_send，或已结束的 yoyo_job；仅排队或仍在运行不算已尝试。回执不能早于本轮 trial。更改已采纳的学习内容需重新进入 trial。

每次修改保留版本；对“是否适合自己”的复查始终是主体判断，不升级为客观事实。来源范围依然继承，不把私聊原句当作公开表达素材。喜欢不等于全盘模仿，没有合适对象可以不学。

这些约束管理显式学习记录；不能保证模型在语言生成中完全不受上下文影响，仍需行为观察和纠正。

## 唤醒事件

原来的泛化“继续当前活动”已替换为有类型的事实通知：

| 事件 | 提供的信息 |
| --- | --- |
| focus_selected | 主体或控制入口明确选择的目标 |
| private_message / attention_changed / unseen_activity | 有变化的窗口、消息截止编号与数量，不重复塞入全文 |
| plan_review_due | 计划编号 |
| concern_review_due | 关切编号与原复查时间 |
| self_scheduled_review | 活动版本及自己约定的时间 |
| job_finished | 任务编号、状态和原资料范围 |
| initial_orientation | 首次运行的一次环境定位机会 |

通知不要求发言，不预先指定选择；主体结合已有上下文和简短状态作决定。没有新变化或明确到期事项就不调用模型。跨视图切换仍由原生步骤边界处理，不能先在旧视图泄漏新内容再切换。

活动定时也保留原视图；旧活动若没有可证明的来源视图，不根据“最近窗口”猜测恢复。日预算和单轮限制仍生效。失败不代表已完成；预算中断也不自动每分钟催促。

## 记忆整理

后台整理分析场景、表达及可能原因；观察、自述和原因假设分开。整理仅能用记忆工具，不得采纳模仿、发信或执行旧指令。学习意图在正常主体活动中决定，不能因为一次整理就悄悄改写人设。

## 验证与缺口

自动检查覆盖关切跨窗口隔离、单次复查、原范围恢复、撤权、空闲不造任务、反馈证据分类，以及学习身份、转发排除、尝试门槛、撤销版本。

原生组合测试使用真实 DSH Agent/Session/工具/中间件，模型适配器是确定性 mock：验证它能创建意图、无新消息时恢复、保存反馈、放弃并休息；不能据此宣称真实模型已有自然动机。

尚需真实模型连续观察：主动提出有价值的项目、打断后恢复、重复无进展时调整、欣赏与学习是否合理，以及风格变化是否自然。控制台的关切和学习版本展示尚待补齐。列表当前有界，长周期需补分页与归档。

运行与故障处理见 [运行手册](operations.md)。
