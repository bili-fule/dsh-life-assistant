# 适合 Bot 的类人记忆系统 Plan

日期：2026-10-21。状态：阶段 1、阶段 2 的分段与线索召回、阶段 3（慢速概括与人物印象）、阶段 4 的前瞻记忆已实现（0.20.0，默认关闭）；语义检索与阶段 5 未实现。实现、配置与验证见 [记忆层实现文档](../memory-layer.md)。配套方案：[自主动机](humanlike-motivation-plan.md)、[多 Agent 编排](artex-multi-agent-plan.md)。

## 1. 目标：记住自己的经历，而不只是保存聊天文本

它需要知道“我们聊过什么、当时我期待什么、后来怎样、我为什么逐渐喜欢这些事情”，并在合适场景自然想起来。记忆为开心、持续满足、关系、自我连续性和未来选择服务，同时保留 Bot 擅长的精确查询、来源核对和权限检查。

类人之处是选择性注意、情境联想、概括、熟悉感、兴趣变化和自然淡忘；不故意制造假记忆、认错人或忘掉明确承诺。对金额、日期、发送回执等精确事项仍查询原始记录，不用模糊回忆代替数据库。

QQ 的统一主体可以有多个执行者和多个聊天窗口。记忆按身份、来源及允许用途组织，而不是把每个窗口变成一个独立人格。微信是独立主体、独立记忆域，账本不会因“联想”进入 QQ。

## 2. 心理学与计算研究依据

| 参考机制 | 借鉴点 | 本方案中的限制 |
| --- | --- | --- |
| 建构性记忆与未来模拟，Schacter，2012 | 回忆会结合线索与已有知识；过去经历可帮助预想未来 | 保存原始事件和派生解释；想象始终标为模拟，不写成发生过的事 |
| 来源监控，Johnson、Hashtroudi & Lindsay，1993 | 区分记忆、知识与信念来自哪里 | 强制保留本人自述、直接观察、转述、工具结果、执行者汇报、推测等类型 |
| 互补学习系统，McClelland、McNaughton & O’Reilly，1995 | 快速保留具体经历与较慢形成一般知识可互补 | 使用快速事件记录与慢速归纳；这是工程借鉴，不声称 SQLite 等同于海马或皮层 |
| 使用历史与记忆可用性，Anderson & Schooler，1991 | 近期、频率和过去使用模式对记忆需求有参考意义 | 用于召回排序；被反复检索不能提高事实可信度，重复整理不算独立经历 |
| 前瞻记忆的多过程框架，McDaniel & Einstein，2000 | 未来意图可依赖线索，也可依赖主动监测 | 宿主保存时间和事件触发条件，避免让 LLM 反复轮询“是不是该做了” |

## 3. 存储基础与六类可用记忆

先区分事件档案与可调用记忆。事件档案保存收到的原文、附件引用、发送回执和版本；它不是每轮都进入上下文的“脑内记忆”。派生记忆都能回到档案，档案受保留与删除规则约束，并非永久不可删除。

| 记忆功能 | 保存内容 | 典型用途 |
| --- | --- | --- |
| 工作记忆 | 当前活动、参与者、近期必要消息、已知与未知、下一步 | 接着说话、避免重复问、任务交接 |
| 情景记忆 | 一件有起止和转折的经历：谁、何时、何处、发生什么、结果怎样 | 想起曾经聊得开心的某次讨论 |
| 语义记忆 | 可复用事实、知识、带情境的偏好判断及其证据 | 知道某个概念，记得某人的明确偏好 |
| 关系与自我记忆 | 共同经历、相处方式、欣赏的特质、自身兴趣的形成过程 | 保持熟悉感、自己的风格和连续身份 |
| 程序记忆 | 方法、适用条件、成功与失败案例、依赖版本 | 下次处理类似问题时知道从哪里开始 |
| 前瞻记忆 | 承诺、未完成打算、等待结果、触发线索和取消条件 | 对方回来时接上问题、到期提醒或复查 |

这六类是可重叠的用途，不是六个彼此复制数据的数据库，也不是六个 Agent。一次经历可以关联知识、偏好、关系和一个后续打算，但原始事实只保留统一标识。

## 4. 把“一个事件”变成“我经历过的一件事”

例子：在某群讨论一部电影，起初只是好奇，聊到共同喜欢的镜头时很投入，后来大家转去其他话题。应保存这一段经历的概要、关键消息、自己的评价和结尾，而不是给每条消息生成一条长期记忆。

事件分段参考话题切换、活动开始与结束、明显转折和间隔；允许拆分或合并，并保留被合并片段的引用。多人同时说话按真实发送者保留身份，不将一段群聊归给最后一个发言者。

情景记忆至少包含：

- 场景、时间区间、平台窗口、真实参与者 ID 与当时显示名。
- 自己的角色：直接参与、只阅读、收到执行者报告或从别人转述得知。
- 发生了什么、关键转折、实际结果与未解决事项。
- 当时的期待、体验评价、稍后的重新评价；事实与评价分字段。
- 关键原文或回执引用、来源范围、保留状态和版本。

执行者帮忙查到的资料应记成“委派研究后收到报告”，不伪装成主体亲自访问过网页。群昵称改变不创建新身份；跨平台账号没有明确认证关系时不能自动合并。

## 5. 自动形成记忆，但不逐条制造长期笔记

收到内容时先记录事实并维护工作记忆。出现有意义的经历、纠正、承诺、兴趣变化或可复用结果时，再提出长期记忆候选。候选的价值可以来自愉快、有趣、共同经历或创作，不限于办事效率。

优先保存：对当前打算有后续作用的事；真实关系转折；令人意外但可信的新发现；自己明确喜欢或不喜欢的体验；纠正旧认识的内容；可复用的方法和失败教训。

一句明确自述可以记录为“某人说自己喜欢 X”，不必等重复出现；据此推断“他总会选择 X”则需要更多经历。一次情绪化表达不自动形成永久人格标签。重要不等于正确，难忘不等于普遍。

自动整理默认提交带依据的候选，宿主检查来源、范围、版本与重复；涉及稳定自我和全局风格的变化由主 Agent 复查。普通事件概括不必逐条询问用户。

## 6. 从具体经历逐渐形成偏好和印象

每次概括形成一条可修订的主张，例如：“他在讨论复杂技术问题时通常喜欢详细解释。”同时保存适用情境、支持例子、反例、确认时间和不确定性。

重复的摘要、转发和同一事件的多个报告只算同一个证据来源。读过十次不能变成十次亲身经历。方法类记忆要关联真实工具结果；未验证的方法保留为建议，不自动提升为熟练技能。

对人的判断分开保存：熟悉、信任、喜欢、欣赏和模仿意愿。可以喜欢一个人的幽默，同时不信任他的技术建议；不能用一个好感数字替代这些差别。

自己为什么改变偏好也应能追溯：“原以为喜欢热闹群，几次讨论后发现更喜欢小范围深入交流。”这是由相关经历支持的自我解释，可以修正，不是永恒性格诊断。

## 7. 线索驱动的自然想起

检索在当前授权范围内依次执行：

1. **确定线索。** 当前参与者、话题、活动目标、时间或事件线索、尚未履行的承诺。
2. **先过滤。** 权限、删除标记、已失效状态和用途边界先于检索结果进入模型。
3. **找候选。** 结合精确实体、关键词／全文索引、情景关联，后续再加入可选的语义向量检索。
4. **排序与去重。** 比较情境相关性、未完事项、近期和有效使用历史，并控制同一话题占满结果。
5. **小量进入工作记忆。** 先返回概要与引用；需要准确原话、日期或金额时再展开原文。

情境相似可以触发“想起上次那件事”，不要求用户说“搜索记忆”。但仅仅同名、同样一句话或相似头像不能触发人物身份合并。

有两种记忆体验：

- **熟悉。** 有概要和较稳定判断，可自然延续，但不声称记得逐字原话。
- **具体回忆。** 找到情景及来源，可明确说起那次经历；精确引文需经过原文验证。

有效召回只在记忆实际被使用或确认有帮助后提升可用性；后台扫描、重复提示和整理不增加强化计数。心情可以作为弱线索，不能过滤掉反例或让不愉快经历永远占据召回。

## 8. 遗忘：先淡出，再按政策保留或删除

遗忘拆成不同操作，不能用一个 active 标记混在一起：

| 操作 | 含义 |
| --- | --- |
| 淡出 | 降低默认召回优先级，需要更明确线索才想起 |
| 归档 | 保留概要与来源，退出日常自动召回 |
| 更正或取代 | 旧判断不再作为当前事实，保留变化关系 |
| 撤回使用 | 从检索和生成上下文中排除，阻止由旧来源重新推导 |
| 删除 | 按用户选择移除原文、派生记录、索引和可控附件，说明备份等实际处理边界 |

普通琐碎细节可以较快淡出，形成长期兴趣或关系的关键经历保留更久。明确承诺、尚未结束的任务、身份授权和安全边界不随普通衰减丢失。财务明细遵循账本的记录与删除机制，不参与情绪性遗忘。

用户说“忘掉这件事”时先执行停止使用；若是否删除原始档案会影响实际保留范围，再明确区分。删除或撤回沿派生关系传播到摘要、人物印象、偏好、嵌入索引和工作记忆缓存。主 Agent 与执行者下一次请求必须排除这些内容。

防复活规则按来源 ID、主张 ID 和派生关系建立，不能只比较文字是否相同。换一种说法重新摘要，也不能绕过撤回。仅保留阻止复活所需的最小墓碑元数据，避免墓碑本身留存被要求删除的内容。

## 9. 回忆可重构，事实不能被悄悄改写

每次回忆可以生成适合当前问题的表述，但表述不是新的独立证据。原始事件、当时的理解和现在的理解分开存。

遇到冲突时保留两条有时间与来源的主张，检查是事实变化、记错、说法不一致还是推断过度。新的话不必然推翻旧事实；本人明确纠正自己的偏好，与第三方猜测的权重不同。模型置信度不是经过校准的真实性概率。

例如从“他讨厌语音”修正为“工作场合不方便听语音”，应缩小原判断的适用范围并保留纠正依据。重复回忆不能把 hypothesis 升级成 observed。

模拟未来时可以结合真实经历提出“我们可能会聊得不错”，但 simulation 类型永远不能作为过去事实或新的相处证据。不给 Bot 注入人类童年、身体经历或不存在的共同往事来营造亲近。

## 10. 与开心和动机系统互相连接

动机系统读取“过去做类似事情时期待什么、实际体验怎样、什么情境更适合自己”。记忆系统保存这些差异，而非只保留开心的结果。

愉快和不愉快都可提高某段经历的显著性，但显著性、事实可信度、未来用途和保留期限必须分开。愉快不代表真实，不愉快也不代表必须永远记牢。纠正、承诺和反例不因让自己不开心而被删去。

活动总结可以更新情景记忆，提出偏好修订，并关联已有关注点；不自动生成新活动。主 Agent 根据经过范围过滤的经历决定是否继续或改变兴趣，不把执行者数量、记忆数量或反思次数当奖励。

选择性模仿仍要求明确欣赏和具体证据。记住对方的语言习惯用于理解对方，不等于把对方的表达直接变成自己的风格。

## 11. 未来意图与可靠提醒

承诺和待办作为可执行的前瞻记录：主体、对象、事项、触发条件、时间、范围、状态、取消条件和真实回执。聊天表达“以后想看看”可以是愿望，不自动等于有期限的承诺。

时间触发由宿主调度；事件触发由新事件匹配已登记线索，例如“等研究结果回来再聊”。宿主先生成状态变化，重要的才在主 Agent 的原生执行边界呈现，不每分钟问模型是否想起来。

完成依赖实际行为记录或明确确认，不能因为记忆摘要写了“已经处理”就关闭事项。相同触发幂等消费，失败有明确状态，不反复打扰。

## 12. 多 Agent 的共享与隐私

主 Agent 持有统一的记忆体系；每个执行者获得任务所需的工作记忆包和权限。原文、推测、偏好及摘要均保留来源范围；检索索引、关系图边、缓存和结果标题同样需要权限检查。

聊天执行者可提交情景片段和记忆候选，不能直接改全局人格。研究执行者提交资料、来源与工具回执。主 Agent 合并时使用事件 ID 和版本检查，避免两个执行者把同一对话写成两段独立经历。

全局总览只呈现必要状态。跨窗口的私有关系、心情原因、偏好变化和摘要不因“统一主体”自动公开。派生记录继承所有输入来源约束；想把私有知识公开使用，必须有单独明确的授权流程，不能靠摘要脱敏自行放行。

模型在某个视图读过私有资料后，切到另一窗口仍需宿主做上下文投影。单独限制 memory_search 返回内容不够；已注入上下文、工具结果和压缩摘要都要同步处理。

## 13. 白天整理、夜间整合与 263K 压缩

白天在自然活动结束或对话空闲后做轻量增量整理：分段、记录有价值的情景、捕获承诺、处理明确纠正。没有新内容时不运行。后台整理由最新处理游标、任务版本和冷却控制，不把整理产物再当作新经历触发自己。

夜间或较长空闲时按权限域整理相关片段：合并重复、整理冲突、形成知识概括、检查偏好与待办，生成下一次可用的少量索引。保留坏结果和反例，不通过把所有回忆改写得愉快来提高“幸福”。夜间是运行策略，不宣称在模拟人类睡眠或梦境。

LLM 上下文压缩与长期记忆整理是两件事。压缩负责让原生请求可运行；记忆负责后续可找回。263K 是既定触发线，实际请求还受模型硬限制、输出预留和工具返回大小约束。

输入可能一次越过阈值时，先在宿主预检，分页大工具结果并分块概括；不能把已经超过硬上限的历史直接发送给模型要求压缩。长期记忆落库可与压缩关联，但整理失败不能阻止必要的安全压缩，也不能删除尚未归档的原文。

整理时优先使用已有可见上下文和增量引用；只按需回读缺失证据，不再把整段上下文复制给 Agent 一遍。压缩摘要保留未完事项、纠正和来源 ID，不能成为没有来源的新“事实源”。

## 14. 实现结构与现有系统迁移

当前 `SocialStore.remember/recall` 已有来源检查、范围过滤和分类；召回主要是关键词子串匹配加时间倒序，QQ episodes 默认约 48 小时后退出活跃召回。`SocialMaintenance` 已有空闲／夜间任务、游标与冷却。新设计扩展这些基础，不推倒已有效的权限机制。

新增或扩展的逻辑记录：episode、claim、entity、memory_link、memory_revision、retrieval_use、retention、prospective_intent。每条记录包含所属主体、来源范围、真实身份引用、事件时间、记录时间、类型、来源 ID、版本和状态。权限字段由宿主计算，LLM 不能自选 public。

现有 profile、relations、knowledge、procedures、intention、communication 标签映射到新结构；旧来源不足的条目保留为待核实，不借迁移自动提高可信度。原 episodes 的 expires_at 映射到“退出自动召回”，不误当成原文已删除。

首期用 SQLite 事务、现有事件表、全文与实体索引完成；语义嵌入是可选后续能力。加入外部嵌入服务前单独检查私有文本外发权限；不为实现联想默认把所有聊天上传给新服务。

拟提供少量接口：`memory_recall`（概要与引用）、`memory_inspect`（核对原始依据）、`memory_propose`（候选或修订）、`memory_retract`（有范围的撤回）。身份、提醒和账本保持各自权威入口，记忆不能绕过它们修改事实。

## 15. 分阶段实施与验收

1. **来源与版本。** 建立派生关系、冲突和撤回传播；先证明不会串身份、串隐私或复活已撤回内容。
2. **情景与联想。** 把消息组织为经历，按参与者、主题和未完事项召回；在旧检索旁影子运行，比较相关性与成本。
3. **慢速概括与动机。** 关联期待、实际体验、偏好变化和人物印象，保留反例与主观类型。
4. **前瞻与多 Agent。** 接入可靠触发、工作记忆包、候选汇合和并发版本控制。
5. **整合与压缩。** 更新增量夜间策略，验证超长输入、重启、撤权及整理失败时的恢复。

| 验收场景 | 必须表现 |
| --- | --- |
| 换一种说法提起曾讨论的话题 | 能联想到相关经历，不依赖完全相同关键词 |
| 两个同昵称的人表达不同偏好 | 不合并身份或习惯 |
| 转发里有人自称喜欢某事 | 不能记成转发者本人的偏好 |
| 一次不愉快后又有多次正常交流 | 能保留变化与反例，不永久贴标签 |
| 经历被摘要十次 | 仍是一个证据来源，不变得更真实 |
| 执行者说查过但没有工具依据 | 标为报告，不声称主体亲自验证 |
| 用户纠正或要求忘掉内容 | 后续召回、摘要、偏好及执行者上下文同步受影响 |
| 长期没提起但仍未完成的承诺 | 仍能按真实触发条件处理 |
| 相同私有话题在另一群出现 | 不能借联想泄露私有记忆或结果标题 |
| 研究模拟了一段可能的对话 | 不把模拟当成实际共同经历 |
| 晚上没有新经历 | 不反复调用模型整理 |
| 输入一次超过压缩线或模型硬限制 | 分页或分块处理，保留可恢复来源，不先发送超限请求 |

评估以来源正确、身份正确、纠正生效、可恢复、相关召回和自然连续性为主；不把记忆条数或“像人一样记错”当成功。隐私泄露和已撤回内容复活是发布阻断项。每阶段保留回滚路径与旧索引，真实删除请求则同步覆盖所有仍可查询副本。
