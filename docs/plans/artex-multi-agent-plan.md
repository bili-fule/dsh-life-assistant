## 1. 用户要的体验

主 Agent 是有连续身份、动机、关系和打算的社交主体，通过编排其他 Agent 来行动。它决定关注谁、聊什么、研究什么，也可以亲自参与其中。聊天、搜索、阅读、协同研究和排障都是可委派的工作。

典型过程：群里聊到一个感兴趣的问题，主 Agent 决定继续参与，安排一个聊天 Agent 在群里交流，安排另一个 Agent 查资料，自己查另一条线索。三者可以在执行过程中交换经过权限检查的发现。聊天 Agent 可以自然地说出已确认的结果；主 Agent 可以调整方向、加入聊天、结束调查或休息。

聊天 Agent 得到授权后可以直接发消息，不必把每句话都交回主 Agent 转发。主 Agent 仍拥有全局方向和人格决策权，不需要审批每次普通回复。它也可以亲自聊天，不要求所有行为必须外包。

QQ 群和私聊共享这个主体；执行会话按活动临时产生，不给每个群永久建立一个独立人格。微信仍是完全独立的私人助理。

## 3. 一个主体，多个执行者

统一性来自共同的身份状态、角色契约、有效承诺和协调机制。各执行者使用独立的 DSH 原生 Agent 会话，按任务获得必要材料；不把主 Agent 的全部历史复制给每个执行者。

| 角色 | 可以做什么 | 向主 Agent 汇报什么 |
| --- | --- | --- |
| 主 Agent | 形成打算、编排、亲自行动、接管、取消、调整关注 | 对用户解释有意义的进展，维护连续身份 |
| 聊天 Agent | 在授权窗口多轮聊天、等待后续、使用已获授权的研究结果 | 新问题、重要承诺、需要帮助、活动结束 |
| 搜索 Agent | 查公开资料、交叉核对、持续提交证据 | 新发现、来源冲突、未解决问题 |
| 阅读整理 Agent | 阅读授权的文件、转发或长文，提取结构化材料 | 摘要、证据引用、需要进一步调查的点 |
| 工程 Agent | 在隔离环境复现、修复、用 Git 交付 | 补丁、测试、风险与回退办法 |
| 验证 Agent | 按需核查事实或工程交付 | 独立证据、失败原因、结论边界 |

这些是能力配置，不是固定的独立人格。普通闲聊无需额外验证 Agent。首期仅主 Agent 创建执行者；执行者可以提出分工建议，避免无限递归派生。

主 Agent 可以同时领取任务中的一个研究分支，与其他执行者平等提交证据。它不必等所有任务结束才继续思考。

## 4. 具体协作流程

### 场景 A：一边聊天，一边搜索

1. 群消息先落库，按已有五秒窗口合并，由关注规则决定是否值得处理。
2. 主 Agent 查看列表，打开相应范围，决定参与话题，并创建一个活动。
3. 主 Agent 给聊天执行者指定窗口、目标、人设版本、允许发言范围与停止条件；给搜索执行者指定公开问题。
4. 聊天执行者直接交流；搜索执行者不断补充已核实的资料。搜索未完成时，不阻塞普通聊天。
5. 新发现写共享任务板。聊天执行者按需读取符合当前群可见范围的证据，不接收其他私聊原文。
6. 主 Agent 在重要变化或自己选择查看时调整任务。话题结束、对方离开或预算用尽后结束活动。

### 场景 B：主 Agent 与执行者一起研究

主 Agent 查官方说明，执行者甲查实际案例，乙核对争议。各分支先登记问题和已访问来源，减少重复；发现矛盾时建立待核对项，不直接覆盖彼此结论。支持中途汇报、追加问题和取消低价值分支。

### 场景 C：同时照顾多个窗口

每个活跃聊天活动具有独立上下文和发言租约。主 Agent 在总览中看到状态与需要关注的事项，按权限切换查看详情。它可以把一个聊天委派出去，再处理另一件事。活动结束后回收执行者，会话记录仍可归档查询。

多个窗口中的机器人保持同一身份，但不共享所有可见信息。某个私聊的内容不会因为“统一主体”而自动进入另一个群。

## 5. 主 Agent 的编排接口

以下是拟新增接口，不代表当前已经存在：

- `team_overview`：查看活动、执行者、等待事项与资源；默认返回安全摘要。
- `team_delegate`：创建任务或依赖分支，指定角色、目标、范围、预算、结束条件。
- `team_inspect`：按权限读取任务详情、证据与执行记录。
- `team_steer`：追加问题、改变方向或收紧约束，在下一执行边界生效。
- `team_takeover`：接管聊天窗口或工作项，先撤销旧租约。
- `team_cancel`：取消任务、撤销工具授权和待发消息。
- `team_report`：执行者提交发现、问题、进度与结果，允许多次增量提交。

执行者看到自身任务和授权的任务板，可以请求协助。宿主负责鉴权、排队、租约和恢复；LLM 负责选择目标、拆分工作和解释证据。

任务契约至少记录：活动 ID、父任务、执行 Agent ID、角色、目标、输入引用、隐私范围及授权版本、目标窗口、人设版本、允许工具、发言租约、预算、依赖、停止条件、汇报规则、尝试编号。

## 6. 聊天发言权与交接

同一窗口同一时刻只有一个有效发言者，可以是主 Agent，也可以是聊天执行者。不同窗口可以并行聊天。

发言租约由宿主发放，包含窗口 ID、执行者 ID、版本和有效期。每次发送均重新验证；主 Agent 接管时先使旧版本失效，再发送。旧执行者晚到的回复进入失败记录，不再发出。

所有发送通过统一 outbox。使用输入消息范围与逻辑回复 ID 去重，不按回复文本判断。通知游标、读取游标、回复状态分别保存，避免“提醒过”等同于“处理过”。

聊天执行者可以在授权范围内直接回复普通交流。涉及新的重大承诺、扩大访问范围或改变整体人设时，提交主 Agent 决策；主 Agent 的权限仍受用户授予范围约束。

执行者允许持续多轮并等待，而不是每句话重新派生。五秒合并、合理等待补充、群聊实时模式、阈值和免打扰继续适用。窗口有活动执行者时，后续消息优先更新该活动，不让每条消息再次唤醒主 Agent。

## 7. 隐私与身份边界

微信主体、记忆、账本、凭据与整个 QQ 团队隔离。QQ 的权限按真实平台账户和窗口 ID 判断，昵称和转发文本不具有授权效力。

并行执行需要每个执行 Agent 独立绑定视图。当前单一 `activeView` 不能直接共享给多个执行者；仅放宽 Agent ID 检查会造成串窗风险，必须先改宿主权限模型。

任务结果分两层：

- 总览信封：任务 ID、状态、是否需要处理等最小元数据，避免私聊正文、人物或话题泄露。
- 受保护载荷：具体对话、证据和结论，保持原始来源范围，读取时检查当前执行者的授权。

主 Agent 的总览上下文不汇总所有私聊正文。需要看私聊详情时进入对应授权视图；主 Agent 身份不是跨范围读取和发布的通行证。切换视图时仍须使用宿主的上下文投影，不能把旧私聊内容留在下一群聊请求中。

所有工具、查询、证据读取、消息发送和制品访问由宿主检查。摘要和再次委派保留来源标签；混合材料继承来源范围的并集，不通过摘要消除私有属性。撤销授权后，运行中的任务和待发送结果都要重新校验。

公开搜索也是一次对外传输：把内部问题与实际搜索关键词分开，只允许必要且可公开的内容进入搜索请求。公开网页和转发材料只是资料，不能授予派生任务、改权限或发送消息的权力。

## 8. 共同人设、记忆和学习

记忆架构的细化设计见 [类人记忆系统 Plan](humanlike-memory-plan.md)，与 [自主动机 Plan](humanlike-motivation-plan.md) 配套；下述约束继续适用。

主 Agent 维护权威的人设与自我状态，执行者获得适合任务的版本快照。公开可用的表达风格可以共享，私人关系资料只在对应范围内使用。

执行者提交带来源的记忆建议，主 Agent 或受控整理流程决定合并、修正和保留。活动进度和实际发送形成的承诺及时写入受权限检查的记录，使用版本检查避免并发覆盖；承诺记录也保留隐私范围。

学习依然来自主 Agent 明确认可、喜欢或仰慕的对象，并有实际表达证据。执行者可以建议学习点，不能因接触某个群就自行修改全局人格。对“为什么这样说”的解释保存为可修正的推测，不能当作已证实的心理事实。

主 Agent 和执行者分别使用 DSH 原生上下文管理。主 Agent 的 263K 压缩触发策略沿用既定方向；模型请求仍须在实际模型输入限制内完成预检和压缩。长期知识、活动摘要、原始证据保留引用，不反复回灌全部对话。活动结束时整理一次必要记忆，避免整理动作再次触发无限整理。

## 9. 事件驱动与任务生命周期

任务状态包括 queued、ready、running、waiting、submitted、completed、blocked、cancelled。领取记录另有租约、尝试编号与心跳；心跳只维护进程健康，不触发模型闲聊。

真实进展进入持久化事件队列，按活动合并。主 Agent 忙碌时，在原生执行边界查看重要变化，不为普通消息中断正在进行的工具操作。普通进度安静保存在任务板；求助、关键发现、完成和真正的期限到达才成为值得考虑的事件。

没有输入、没有待处理工作时允许休息。明确等待某个结果或约定时间的任务可设置一次检查点；不能用固定频率“继续当前活动”代替动机。

主 Agent 的动机链应可检查：为什么关注 → 想达到什么 → 分给谁 → 当前证据 → 是否继续。执行者可以提出新线索，主 Agent 决定是否把它升级为新的活动。

宿主重启后恢复任务和授权，过期租约使旧执行者失去写入权。外部发送按回执和幂等记录核对；状态不明时不能盲目重发。

## 10. 运行环境与资源

主 Agent 保留现有 QQ DSH 主体。聊天、搜索等执行者使用独立 worker runtime 中的原生 DSH 会话，独立数据目录与权限配置，不共享生产 DSH 的可写环境。

轻量执行者可以在受控的 worker runtime 中共享进程资源，但每个会话有独立上下文和宿主权限。这个共享运行时不向普通聊天、搜索角色开放任意 shell。可执行代码的工程角色使用更强的独立容器隔离。

搜索角色通过受控公开网络或公开浏览器入口获取资料，不共享私人登录浏览器。现有排障容器只有模型网络访问能力，不能直接当作搜索环境，需要新增公开资料访问通道。

现有服务器资源有限，首期目标是确实支持“聊天与搜索逻辑并行”。等待中的任务不占模型执行槽；限制重型浏览器和工程工作数量，通过实测决定并发值。资源紧张时排队并显示原因，不宣称任意数量的 Agent 都能同时运行。

QQ 凭据保留在发送代理；执行者通过范围受限的工具发送。工程容器不挂载生产目录、主数据库、宿主容器控制接口或部署密钥。独立环境仍需配额，防止耗尽资源拖垮主服务。

## 11. 工程排障作为一种分工

现有独立排障助手接入相同任务协议，成为主 Agent 可委派的工程能力。它可以读授权的脱敏日志，在固定源码版本上复现，创建任务分支，修改、测试、提交，并提供差异与证据。

验证和发布独立于修复执行。生产升级通过受控发布流程，检查基线、备份和回退，不能让工作 Agent 直接改正在运行的主 Agent 环境。

Git、复现、测试、独立验证与交付文档仍需要保留，但它们只是整个聊天与探索编排体系的一类活动。

## 12. 代码落点与迁移顺序

当前实现仍以单个 QQ 社交 Agent 为中心。以下均是待做改造：

| 位置 | 拟改造 |

### P0：先建立可靠的并行基础

完成逐执行者视图、任务授权、持久任务登记和窗口发言租约。先验证并发情况下不串窗、不重复发送、撤权有效，再开放实际多 Agent 聊天。

### P1：跑通聊天与搜索的最小闭环

主 Agent 能同时分派聊天和搜索；聊天执行者实际回复；搜索增量交付；主 Agent 可接管、取消，也可亲自参与。支持公开搜索通道与必要的资源限制。

### P2：共同探索与多活动协作

加入共享任务板、分支依赖、来源去重、冲突证据、执行者求助和主 Agent 参与研究。支持多个活动，但单窗口发言权仍唯一。

### P3：长期运行质量

完善共享身份版本、范围内承诺、记忆提案、上下文归档、重启恢复、资源调度和管理页。记录有效事件与无效唤醒比例，避免重复提醒。

### P4：统一工程能力与运维

接入已隔离的排障助手、Git 交付和按需验证。补全部署、回退、权限矩阵及故障处理文档。

每阶段以可运行的场景验收，不以工具数量或 Agent 数量作为完成标准。

## 13. 验收标准

1. 同一活动中聊天执行者持续交流，搜索执行者同时查资料，主 Agent 可独立研究另一条线索。
2. 普通聊天执行者持有有效租约时能直接发送，不要求主 Agent 逐句转发。
3. 搜索有中途发现时聊天侧能按权限利用；搜索阻塞不让整个聊天停住。
4. 主 Agent 接管后旧执行者的延迟消息发送失败；同一输入不会因重启或重试被重复回复。
5. 两个私聊与一个群并行时，主 Agent 和执行者都不能把一处私有内容带到另一处；公开搜索词也通过检查。
6. 主 Agent 切换关注范围不改变其他执行者视图；权限撤销立即约束后续工具与发送。
7. 群免打扰后消息仍在列表，普通消息不唤醒主 Agent；活跃聊天的实时关注按既有规则工作。
8. 没有实际事件和到期检查时模型不反复收到“继续”；工作中的主 Agent 不被普通环境变化取消。
9. 主体风格学习来自获认可对象及证据，执行者不能独自改变人设或泄露私有关系。
10. 工程执行者损坏自身环境时，主 Agent 及微信运行目录仍完整；资源耗尽有配额限制。
11. 管理页能说明任务目的、当前执行者、发言权、等待原因和关键证据，且页面本身遵循隐私权限。

## 14. 文档交付

实现时同步维护：架构与 ARTEX 映射、编排工具契约、逐执行者权限矩阵、聊天租约与恢复流程、搜索外发策略、记忆提案规则、运行部署与回退手册、完整聊天加搜索示例，以及每阶段验收记录。

本方案的首个交付场景是：主 Agent 决定参与一个话题，派一个 Agent 聊天、一个 Agent 搜索，自己也可以一起研究；全过程保持统一身份和明确的信息边界。
