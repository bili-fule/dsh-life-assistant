# 可交给实施 Agent 的 Goal 提示词

请以持续迭代的 goal 完成 `D:\project\dsh-life-assistant` 的 QQ 连续主体与并行活动分支改造，直到实际运行和验收达标。首先阅读适用的 AGENTS.md、当前代码与部署记录，以及这两份主计划：

- `docs/plans/continuous-qq-subject-plan.md`
- `docs/plans/unified-subject-parallel-branches-plan.md`

它们优先于旧计划中冲突的按窗口隔离主体上下文、固定角色分工及发布限制。`docs/plans/dsh-native-orchestration-migration-plan.md` 可参考，但必须核对当前安装 DSH 的真实能力与已修复项。

目标体验：yoyo 是一个持续的 QQ 主体，像一个人操作手机。切换群聊、私聊或浏览器不能丢掉意图、承诺和进度。它可自己聊天、浏览、研究，也可创建通用活动分支并行工作。分支延续同一人格与活动意图，拥有独立工作上下文，通过共享活动和增量事件直接交流；无需事事经主 Agent 转述，也不只在结束时汇报。主 Agent 不应退化为转发员。

明确约束：QQ 私聊不放敏感信息，QQ 内容边界用提示词，不增加隔离发言/审核 Agent，不因读过别群而禁止发言或浏览。微信必须继续保持独立主体、数据库、凭据和权限。保留稳定收件人、授权版本、发言租约、发送去重与 uncertain 处理。工程分支保留独立环境。全部模型循环使用 DSH 原生机制，不重写 LLM 循环；能复用原生 subagent 管理则复用，缺失能力如实记录，不伪造支持。

先审计现场、复现 xmfu 切窗后丢目标的问题，再按主计划的小阶段实现：连续上下文与活动索引 → 至少两个真正并行的通用分支 → 双向/同级事件同步 → 版本、接管、取消与恢复 → 真实模型验证和部署调优。复用已有任务板、steer/report、记忆与动机代码，避免新建重复权威。消息采用持久事件、去重与游标确认，在原生安全边界交付；禁止固定“继续当前活动”提示驱动和高频空轮询。

你可以在当前任务中委派有明确边界的代码、测试或审查子任务，但统一负责集成与验收。保护其他人的未提交修改；每阶段提交有意义的代码及文档并推送到既有仓库。沿用既有部署授权，冻结 SHA、备份配置和数据、验证后部署；不要通过旧数据库回滚覆盖新消息。真实外部发信限于已有授权，不向无关群制造测试消息。

必须用可检查证据验收：切窗仍记得为什么来；读取/浏览有真实回执；两个分支运行时间重叠；发现能在完成前被另一分支收到；同级问答不依赖主 Agent 转述；接管后旧分支不能发送；冲突不静默覆盖；压缩/重启保留目标和未完成事项；不重复 create 已有 Session；微信始终独立。记录事件投递和模型响应的不同延迟，并对比串行/并行的耗时、质量和成本。计量缺失不得记为实际 0。

持续更新进度文档，区分已设计、已实现、已测试、已部署与未验证。不要把启动成功、注册工具、单次最终回复或 Session ID 相同当作完成。遇到失败先定位并修复、调整方案再验证；只有必要信息或外部条件确实缺失时才提问。最终交付准确的架构说明、测试证据、Git 提交/推送状态、部署版本、回滚办法及残余限制。
