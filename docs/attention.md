# QQ 窗口列表、注意力与免打扰

## 操作顺序

收到消息先等待固定 5 秒合并窗口，再以窗口动静唤醒同一个 QQ 原生 Agent。私聊也进入总览，不自动打开其聊天内容。Agent 调用 `yoyo_inbox` 获取已授权群聊和私聊的元数据（稳定 handle、名称、未读数、是否被 @、免打扰状态），自行选择继续当前活动、打开某个窗口或休息。

`yoyo_open` 只允许选择曾经通过列表获得且仍获授权的 handle，切换在本回合结束后进行。`yoyo_read`、搜索和原消息工具只能访问当前窗口；总览不能直接读原文。列表不含消息内容。已有任务的定时复查和记忆维护仍可恢复原有资料范围，不重复要求人工选择。

## 免打扰

Agent 可用 `yoyo_mute({target, muted:true})` 设置持久免打扰，用 false 取消。它只控制插件对 Agent 的消息注意力，不修改 QQ 客户端通知设置，也不是群禁言。

免打扰窗口的消息和附件索引继续入库，未读和 @ 标记保留在列表；Agent 可随时主动打开阅读。消息和 @ 都不会触发注意力唤醒。取消免打扰时跳过此前消息的通知游标，避免积压消息突然唤醒；原文和未读不删除。主动安排的任务、复查和后台记忆维护是独立调度，不受消息免打扰取消。

## 通讯录授权

默认仍需运营者授权。运营者将 QQ 社交数据库的 `qq_directory_access` 设置为 true 后，`qq-discover` 从已验证机器人账号的真实好友/群列表同步并授权首次发现的窗口。明确撤销过的窗口（版本已变更）不会自动恢复。消息文本、昵称和合并转发不能授予授权。

QQ 与微信仍使用独立 Agent、数据库和原生会话；这次开放仅限 QQ。跨窗口发送仍执行目标授权与资料来源检查。

## 环境更新与执行边界

消息接收只入库，不调用 cancel、不排入新提示，也不切换 Agent 的资料窗口；后台记忆整理同样不会被私聊或 @ 取消。原生 Agent 忙碌时调度器直接返回。

每个 `agent/pre-step` 原生行动边界把已完成 5 秒合并的未通知动态写入动态系统状态 `environment.noticed`，仅包含窗口元数据；同时推进通知游标，不标记原文已读。Agent 在本来的下一次推理里自行察觉，忽略后不会因同批未读消息再次启动回合。没有新动态时清空这一瞬时提示。维护回合不消费消息注意力。

已安排未来复查的 working/waiting 活动继续等待原定时间，普通消息和 @ 不提前启动它。空闲时仍可由未曾呈现的私聊、@ 或普通群动态按原有优先级与冷却规则唤醒一次。定时关切、任务结果和自己安排的复查优先使用其原有资料范围。

DSH 当前接口在模型完全空闲时仍需要一次原生请求作为启动入口，因此空闲唤醒保留短的固定“自主评估”入口；具体环境变化移至动态系统状态，不再逐条伪装成用户消息。记忆维护仍有其有界维护指令，明确用户请求仍是用户消息。这不是后台持续推理，也没有新增常驻的模型循环。

## 按参与程度调整群聊钝感

`yoyo_attention` 对每个群独立设置，可在任意正常活动调用；维护回合不能修改。`yoyo_inbox` 同时返回每群的有效策略。

- `mode: auto`：默认以最近 5 分钟消息数除以 10 向上取整作为条数阈值，最少 3 条、最多 50 条。大致积累该群平时 30 秒的流量；流量越大，条数阈值越高。最长等待默认 120 秒，两次提醒间隔至少 60 秒。条数或最长等待任一达到即符合提醒条件；仍服从主体休息、工作复查及普通群消息调度冷却。
- `mode: realtime`：用于刚刚参与且想继续的群聊。默认 10 分钟，`durationMs` 可设置 30 秒至 1 小时。新消息经过原有 5 秒合并即可形成提醒，不再等待普通群的全局冷却；可以唤醒等待回复的空闲主体，但不取消执行中的行动、不提前其已安排的工作复查。到期自动回到 auto，也可随时主动退出。它不等于持续调用模型。
- `mode: custom`：`minMessages`（1–1000）、`maxWaitMs`（5 秒–24 小时）、`minIntervalMs`（0–24 小时）可单独设置，未填字段使用自动默认值。
- `mentionBypass`：是否允许 @ 跳过条数/最长等待阈值，默认 true；仍服从 5 秒合并及本群提醒间隔。免打扰始终优先，包含 @。

低于阈值的群消息只留在窗口列表，不出现在动态提醒里；即使 Agent 正在处理别的事情也不会逐条提醒。达到阈值后一次呈现积累元数据，推进通知游标，但不标记聊天已读。Agent 想继续聊时可以自行开 realtime，失去兴趣时恢复 auto。系统不假装能够从“发过一句话”准确断定它是否还想继续。

## 已呈现不等于已读取

通知游标只防止重复唤醒，不能代表已读。`environment.pending` 持久保留已提醒但尚未读取的窗口元数据，跨窗口/重启仍可见；当前窗口同时暴露 `currentWindow.unread`。只有实际读取或显式 `yoyo_dismiss` 才移出待关注状态，dismiss 不标记原文已读。待关注状态本身不重复唤醒，也不强制回复。

## 窗口切换与事实核验

`yoyo_open` 结果明确区分当前焦点和下一回合目标。当前回合留在原窗口不代表被强制切回；下一回合从 `currentWindow` 确认已生效。读取工具返回实际 target 和窗口名称。宿主保存 `navigation` 打开/读取计数、时间和消息编号等元数据，不保存聊天内容；它跨窗口可见，但已撤销的目标不返回。历史活动描述仅是 Agent 自述，不能代替当前工具核验。

原生集成覆盖独立 QQ 主体的私聊→列表→群聊读取→私聊，验证焦点稳定、读取计数保留且群聊内容不进入私聊请求。
