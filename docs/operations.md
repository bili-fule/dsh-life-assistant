# 动机模式运行与排障

## 升级

1. 核对 DSH 原生扩展 requestViewVersion=1，QQ/微信使用各自 Session 与工作区。
2. 等待当前原生回合结束，停止 dsh-life-assistant 服务，备份代码、生产配置和数据目录。SQLite WAL 与主库一起保留，勿仅复制正在写入的主库。
3. 更新插件包；保留生产 cordis 配置、凭据文件和原生扩展版本。本版增加四张独立表，不删除旧消息、活动、计划或记忆。
4. 启动服务，核对管理 API 的 nativeReady、微信绑定、原生会话 ID、QQ 接入状态。先做不发信的内部联调，再观察实际自主活动。
5. 不因一次失败或观察超时重复启动服务；先查原生请求和现有进程。

新表：yoyo_concerns、yoyo_concern_feedback、yoyo_learning、yoyo_learning_versions。记录位于 QQ 独立数据库中，不能拷贝进公开仓库或微信库。安装包包含 docs；项目私有 plans 不发布。

## 诊断

| 现象 | 检查与处理 |
| --- | --- |
| 界面仍有“继续当前活动” | 看时间是否是旧历史。升级不删除历史；新普通事件应显示环境变化及类型。不要凭旧记录认定新代码未生效 |
| 休息很久不行动 | 检查是否有明确 reviewAt、活动 wake_at、任务结果或新消息；无事件、无到期项允许持续休息。再看暂停、日预算和原生运行状态 |
| 关切到期没再次触发 | 核对是否已有持久请求领取该机会、请求失败、资料授权撤销或日预算不足；查看原生轨迹及 yoyo_turns。失败不自动无限重试，可在原范围重新决定复查 |
| 继续处理旧任务 | 查看旧计划/活动是否仍未结束。通过正常主体工具将已完成事项完成或取消，保存新意图；不要只靠新一条“继续”猜测意图 |
| 反馈说完成但没有现实结果 | self_report 是主观报告，不是执行证据。检查实际工具 receipt、退出状态、文件和平台回执；不要把模型文字当作现实成功 |
| 学习工具拒绝采纳 | 核对稳定身份的两条独立原文、是否为转发、是否先进入 trial、回执时间、任务结束或消息已送达。主观复查不能替代实际尝试 |
| 风格变化不合适 | 将对应学习记录 retired，并要求主体停止沿用。版本保留用于核对；生成风格无法仅靠数据库状态绝对约束，仍应观察实际表达 |
| 新窗口读不到关切或学习记录 | 这是来源范围限制；不要通过改库中的 scopes 绕过。公开研究应从 public 开始，不能将私人经历直接变成公开材料 |

## 回退

在空闲时停服务，恢复已核对版本的代码和生产配置。若需回滚数据，恢复完整停机备份后再启动；先核对回退期间可能已送达的消息及副作用，避免旧发件队列重复投递。不要删除新表试图代替备份恢复。

保留原生 DSH 轨迹、失败请求 ID 和回执用于本地排障；对外报告只给脱敏摘要。任何版本都不能从私有生产库生成公开测试样本。

## 验收边界

实际模型一次选中项目、设定复查并行动，只证明该次闭环可工作。自然关系、稳定兴趣、持续成长、低打扰与跨夜稳定性需要连续观察。自动化测试证明的是明确的调度、身份、范围和状态约束。
