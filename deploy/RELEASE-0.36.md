- 生产基线：`9a50ab6`（0.25.0），验收见 [部署验收记录](../docs/deployment-025-2026-10-21.md)。
- 开发版范围：`9a50ab6..HEAD` 共 13 个提交，其中 `40d620a`、`7b22aad` 是运维方在部署期间另行提交的调度与浏览器修复，其余为本次开发。
- 逐条验收状态：[三份计划的验收自查表](../docs/plan-acceptance-audit.md)（由测试自我约束）。

## 2. 数据迁移

**结论：纯增量，不需要手工迁移脚本，也不删除任何历史数据。** 打开数据库时按需补列／建表：

| 对象 | 变化 | 旧数据如何处置 |
| --- | --- | --- |
| `yoyo_team_usage` | 新增 `tokens_reported` | 原有正数 Token 补标为「已上报」（旧代码只在真实回报后写入）；0 保持「未上报」 |
| `yoyo_team_memory_packs` | 新表 | 新建为空 |
| `yoyo_team_memory_candidates` | 新表 | 新建为空 |
| `yoyo_concern_wakes` | 新表 | 新建为空 |
| `yoyo_memory_wakes` | 新表 | 新建为空 |
| `yoyo_team_tasks` | 既有 `failures/retry_at/...` 等列保持不变 | 不动 |

证据：`test/upgrade-path.test.mjs` 会把数据库回退成「没有上述表和列」的旧形态，再让新代码打开，断言原有记录、游标与用量不变、新表为空且可用；第二项测试断言重复打开同一库是空操作且 `integrity_check` 为 `ok`。上线前建议在**生产库副本**上先跑一次 `npm test`（默认用临时目录，不会碰生产库）。

## 3. 配置变更

没有新增必填项。可选开关（都有默认值，不写即沿用旧行为）：

- `autonomy.memory.migrateLegacy`：只把旧 `yoyo_memories` 逐条登记为待核实主张，跑一次即幂等（0.25.0 已在生产开启过）。
- `autonomy.team.retryBlocked` / `retryAttempts` / `retryDelayMs`：失败任务自动重排，默认关闭。
- `autonomy.memoryMaintenance.pageEvents`：夜间／空闲整理每次覆盖的原文条数，默认 120（1–1000）。
- `engineer` 角色需要在 `autonomy.team` 下保持 SDK 与隔离执行服务可用；未配置时调用会直接报错，不会静默失败。

## 4. 上线步骤

1. 备份：源码快照、配置、数据库与回滚脚本放到 root 私有目录（参考 0.25.0 的 `<备份目录>` 做法）。
2. 停止服务，确认执行者已结束、数据库已关闭。
3. 部署 `0.36.0` 源码，`npm ci`（或沿用现有依赖目录），`npm run check`。
4. 在**副本库**上跑 `npm test`（233 项）与 `node test/team-native-smoke.mjs <SDK 入口>`（可选，需要真实 SDK）。
5. 启动服务，按下面验收点逐项核对。
6. 观察一轮：管理页团队面板出现、Token 未上报时显示「未上报」、夜间整理只跑一次。

## 5. 上线验收点

- `GET /api/state` 的 `autonomy.team` 有 `concurrency` 与 `tasks`，且 `tasks[].tokensReported` 是布尔值。
- `GET /api/state` 的 `autonomy.memoryMaintenance.next` 能给出 `{job, reason}`：安静时 `reason` 非空。
- 管理页「团队编排」：面板可见、三个操作按钮按状态出现、「查看资料」需要二次确认。
- 数据库里 4 张新表存在且为空；`yoyo_team_usage` 有 `tokens_reported` 列。
- 撤权一个窗口后：该窗口的视图立刻失效，管理页按任务查看资料返回失败。
- 夜间整理想定：同一晚只出现一条 `night` 作业；下一晚才可能再出现。

## 6. 回滚

1. 停止服务，保留当前数据库副本（新表与新列在旧代码下**不会被读取**，回滚旧源码不会损坏数据，但旧代码看不到 0.26–0.36 期间写入的作业包、候选与唤醒计数）。
2. 换回 `9a50ab6` 源码与配置，启动服务。
3. 若必须回到上线前的数据状态，使用备份目录里的完整恢复脚本；**上线后若已有新消息，先另存当前数据并确定保留方式，不要直接覆盖**（0.25.0 验收记录里同样的告诫仍然适用）。

## 7. 明确不在本次范围内

- 语义向量检索（记忆层）：需要外部嵌入服务，前置是私有文本外发评审。
- 容器级资源隔离、执行者的排障容器：需要容器运行时，且是否开放属于安全取舍。
- 阶段 5 的真实运行验收与数值校准：需要真实模型与真实群持续观察；0.25.0 的验收只证明链路可用。
