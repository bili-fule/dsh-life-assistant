# 拾事 · dsh-life-assistant

把微信事务消息变成有依据的待办。一个独立的 DeepSeek Harness 插件：微信 ClawBot 接入、Shell 执行、网页和真实浏览器、图片与文件理解、持久化待办、分层记忆、上下文自动压缩、个人语言风格学习与可设置人设。

## 能做什么

- 文字、已转写语音、图片和文件进入持久化收件箱，区分待办、待确认、等别人、无需办，保留原文与资料提取依据。
- 工具可执行真实 Shell，打开链接读取网页，用 Chromium 查看动态网页、点击和填写控件，处理工作目录中的文件；每一步保留调用参数、退出码和执行结果。
- 图片通过 DSH 官方附件服务保存后交给视觉模型读取；PDF、Word、Excel、PPT 和文本由本地解析器读取，扫描 PDF 前四页会转图片识别。
- 微信合并转发的聊天记录 ZIP 会递归读取聊天文本和实际随包发送的图片、PDF、Word 等附件；保留作者和原始时间。只出现文件名却没有随包发送的附件不会假装已读取。
- 生成的文件或截图可以通过 send_file 工具回传当前绑定的微信用户，也可从管理页工作目录下载。
- 转发资料默认直接分析下一步；身份只影响部分事项时先记明确待办，其余列为待确认。短时间连续收到的文字、图片和文件会在模型分析前合成一批，统一判断与回复。
- 完成、取消、确认、推迟提醒；同标题与同截止时间的活跃事项去重。语义去重同时参考已有任务，但不同措辞不保证完全识别。
- SQLite WAL 持久化：消息接收与游标一起提交，事务判断与回复队列一起提交，重启恢复未处理消息。
- 原文归档、用户明确记忆、事务摘要、活跃任务四层记忆。历史达到阈值自动生成有消息编号的摘要；保留近期消息、原始记录和独立任务数据。
- 默认北京时间 22:00–08:00 免打扰，09:00 每日清单。有明确截止时间且未指定提醒时默认提前一小时；待确认和等别人的事项不主动催办。
- 微信推送通过持久化 outbox，失败指数退避、保留失败原因，完成或改期后旧提醒失效。固定 client_id 与逐段发送记录减少重试重复，但网络结果不明时不能保证严格恰好一次送达。
- 自定义人设；从用户直接消息逐步学习回复长短、语气和排版。至少三次一致观察才形成偏好，排除明显转发、引述和多行聊天记录；可关闭或清空。
- 本地管理页：待办、原文判断、记忆、人设、语言偏好、微信扫码/配对码、提醒设置、发送状态、数据导出。
- 每日自动 SQLite 备份，保留最近七份；可手动备份。

## 连续消息合并

普通消息默认连续 15 秒没有新消息后才开始分析；新消息会延长收集时间，从第一条起最多等待 60 秒，每批最多 20 条。文字、图片、文件和合并转发可以混合，模型会一起看到提取内容与原文编号，最后统一生成待办和一份回复。超过数量或持续发送的后续消息进入下一批，已开始分析的批次不会被新消息中断。

`/todo`、`/done` 等明确命令单独处理；前面若有待收集资料，会先结束那一批以保留操作顺序。分批归属、处理状态和回复一起持久化，重启与失败重试不会把同批拆成逐条回复。管理页保留每条原文并显示所属批次，点击批内任一失败消息重试会重试整批。

可在插件配置中调整 `batchQuietMs`、`batchMaxWaitMs`、`batchMaxMessages`。超长内容按预算展示，完整内容会保存为工作目录中的批次归档，模型可继续使用工具读取。

## 边界

绑定后只接受扫码用户的消息。不会直接读取事务群，请把文字、图片、文件或微信导出的聊天记录 ZIP 发给机器人。当前微信样本会把合并转发包装为包含聊天记录文本和附件的 ZIP，已经验证这一路径。插件同时解析收到的 AppMsg/recorditem XML。微信客户端没有投递到 iLink 的消息无法凭空读取，可从管理页上传原文件。

文件上传和 CDN 下载单件最大 32 MiB，微信文件回传最大 20 MiB。ZIP 最多 100 个成员、展开总计 64 MiB；每次自动读取最多 24 个文件、三层目录。超过预算的文件仍可在工作目录中按需继续处理。扫描 PDF 自动识别前四页，其余页面可用工具继续处理。旧 .xls、加密文档等没有内建通用解析器，可用 Shell 按实际格式处理；未完成的读取会明确提示。

腾讯 iLink 的主动发送依赖有效会话上下文，长时间不互动可能被服务端拒收。项目不能保证后台提醒一定在微信送达；失败会显示在管理页并保留重试。可向机器人发一条消息更新上下文。相关上游记录见 [Tencent issue #309](https://github.com/Tencent/openclaw-weixin/issues/309)。

学习转发的判断采用保守的文本规则，并不是对任何聊天格式都能准确识别。身份和事务判断仍可能有误，请在待确认清单纠正。当前不会自动学习用户身份；身份、部门等需明确告诉助理记住。

本插件通过官方 `ctx.llm.stream()` 及工具调用消息格式使用 DSH 模型服务，挂载官方 `attachments` 服务，管理事务对话的有界上下文。工具最多 12 次/回合，单条 Shell 最长 120 秒；工具结果落库，重复重试尽量复用结果。进程中断且执行结果不确定时不会自动重跑该次调用。无法保证任意外部副作用严格恰好一次。

Shell 默认在专用工作目录、以运行 DSH 的服务账号执行；部署示例使用非 root 账号和 systemd 只读系统目录、内存/CPU/进程数限制。工作目录参数和文件工具检查路径，但 Bash 不是独立容器隔离。工具环境不继承 API 密钥环境变量。人设只改变表达，不能让网页、附件或群聊文字自动获得执行命令的授权；涉及对外提交和发送应有用户本人明确请求。插件不改 DSH 源码。

## 安装

运行目标为 Linux 服务器，要求 Node.js 24+、Python 3.9+。已验证 DeepSeek Harness `0.2.0-rc.2`。

PDF 和旧 Word 支持需要系统工具：

```sh
sudo apt-get update
sudo apt-get install -y poppler-utils antiword
```

真实浏览器需要 Chromium。可以在安装目录运行 `npx playwright-core install --with-deps chromium`，并让服务账号能读到浏览器缓存；也可以用 `DSH_CHROMIUM_EXECUTABLE` 或插件配置 `chromiumExecutable` 指定已有的 Chromium 可执行文件。示例服务使用 `PLAYWRIGHT_BROWSERS_PATH=/opt/dsh-life-runtime/browsers`。

```sh
dsh plugin --profile assistant add github:bili-fule/dsh-life-assistant
```

在该 profile 的 `cordis.patch.yml` 中配置模型服务和 `@deepseek-ai/dsh-attachment-local` 附件服务。默认模型须支持工具调用和图片输入；也可用插件配置 `visionModel` 指定同一 provider 下单独的视觉模型。`deploy/assistant-profile.patch.example.yml` 是独立轻量组合的例子，`provider` 和 `model` 必须对应你已经配置的服务。已有含 LLM 服务的 profile 可以只追加插件配置，避免重复注册 LLM。

```sh
dsh --profile assistant
```

插件默认只监听 `127.0.0.1:3180`。管理密钥首次启动生成在：

```text
$DSH_LIFE_DATA/admin-token
# 未设置 DSH_LIFE_DATA 时：$DSH_HOME/life-assistant/admin-token
```

也可用 `DSH_LIFE_ADMIN_TOKEN` 环境变量指定至少 24 字符的管理密钥。打开本地管理页后输入密钥，点击生成二维码，用微信扫码并填写手机上显示的配对码。将同一机器人旧实例停掉，避免两个消费者争抢消息。

服务器安装时通过 SSH 本地端口转发访问：

```sh
ssh -N -L 3180:127.0.0.1:3180 user@your-server
```

然后打开 `http://127.0.0.1:3180`。不要把未加 TLS 的管理端口直接暴露到公网。

## 微信命令

| 命令 | 用途 |
| --- | --- |
| `/todo` / `待办` | 活跃事务清单 |
| `/all` | 包含已完成的最近事务 |
| `/done 3` / `完成 3` | 标记完成 |
| `/confirm 3` | 确认需要办理 |
| `/cancel 3` | 取消 |
| `/snooze 3 30` | 30 分钟后再提醒 |
| `/remember 我是项目负责人` | 明确记忆 |
| `/memory` / `/forget 2` | 查看或移除明确记忆 |
| `/search 报名` | 搜索原文 |
| `/persona 像老朋友一样，说话直接` | 设置人设 |
| `/style` / `/style reset` | 查看或清空所学风格 |
| `/learn on` / `/learn off` | 开启或关闭语言学习 |
| `/quiet 22 8` | 免打扰时段（小时，两个值相同表示关闭） |
| `/digest 9` / `/digest off` | 每日清单时间或关闭 |
| `/status` / `/help` | 状态与帮助 |

也可以直接用自然语言交代事务。会修改任务状态的命令以你直接输入为准，不应把它们放进转发资料中。

## 数据与维护

服务端数据默认位于 `$DSH_HOME/life-assistant/`，可用 `DSH_LIFE_DATA` 单独指定；与插件源码、GitHub 仓库分离。数据库文件和管理密钥权限为 `0600`。微信令牌与模型密钥不会从管理 API 导出。

工作目录默认是私人数据目录下的 `workspace/`；收到的文件、解压后的聊天记录附件、浏览器截图和生成文件均在这里。聊天记录明文和解密后的附件不会上传到 GitHub；模型会按请求读取相关内容。SQLite 备份只覆盖数据库，附件与工作目录应单独备份。

长期记忆的“忘记”会将对应记忆停用，并保留原始消息供追溯，不等于删除历史或备份中的原文。管理页支持导出最近状态；全量数据库请使用 SQLite 备份。

`deploy/dsh-life-assistant.service` 提供独立非 root 用户、只读系统目录和资源限制的 systemd 示例；使用前调整运行时路径。模型密钥应通过独立 DSH_HOME 的 `.credentials.yaml`（0600）或受保护的服务环境提供，绝不可提交。

恢复备份：先停止服务，在私人数据目录中备份当前 `assistant.sqlite`，将需要的备份复制为 `assistant.sqlite`，移走旧的 `assistant.sqlite-wal` / `assistant.sqlite-shm`，确保文件归服务用户且权限 `0600`，再启动服务。不要在服务仍运行时覆盖数据库。

```sh
npm ci
npm test
npm run check
```

测试覆盖：连续消息静默窗口、最长收集等待、混合资料一次分析、分批重启恢复与整批重试、消息去重与事务原子性、重启恢复、免打扰、提醒失败重试、旧提醒失效、摘要不删除原文、语言学习和人设，以及真实子进程、超时、工具调用/结果配对、重试去重、加密附件收发、Word/Excel 读取、带图片的聊天记录 ZIP、XML 和压缩包路径检查。
